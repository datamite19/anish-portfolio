Build

How I think about data systems

A pipeline is only useful if people can trust what comes out. These are the questions I ask of any data workflow, drawn from my work and my study of system design.

  • Safe to re-runA load that runs twice should not create duplicate records.
  • Check at the boundaryValidate data when it enters, not after someone spots a wrong report.
  • Agree the schemaClear field definitions between source and consumer prevent silent breakage.
  • Make failure visibleLogs and alerts so problems surface early, with a clear place to look.
  • Test and version itScripts live in version control and are tested before they run on real data.
